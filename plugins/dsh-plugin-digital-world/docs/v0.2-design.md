# 数码世界 v0.2 设计方案（第二版）

> 状态：提案，待确认
> 修正方向：
> - **File Island 地图完全按我们的想法重新设计**，不照搬原游戏布局
> - **屏幕固定 1280×720**
> - **数码兽数量以最新 Wikimon 统计为准**
> - **只以数码兽本身的数据为基础**（等级、类型、属性、必杀技、官方设定、进化关系）
> - 养成、战斗、地图、界面、任务、时间等系统全部由我们原创设计
> - **初始不固定搭档**：赠一颗随机数码蛋，孵化出随机幼年体
> - **支持多数量持有**：战斗吸收、重构收服、捡蛋、任务获得

## 1. 数量口径（重要）

最新 Wikimon 统计（截至 2026 年）：

| 口径 | 数量 | 说明 |
|---|---:|---|
| Wikimon「List of Digimon」全表 | **1,614 只**（2026-07-25） | 包含变体、漫画/游戏/未收录形态 |
| 官方 Digimon Reference Book 有档案的数码兽 | **1,325 只**（2026-10-30） | 有官方等级、类型、属性、必杀技、设定文本 |
| Appmon Reference Book | 148 只 | 与数码兽分开，默认不计入 1,614 |

**本方案默认：**

- 图鉴总目标 = **1,614 条 Wikimon 全表**
- 其中 **1,325 条**必须有完整官方字段（等级/类型/属性/必杀技/官方 profile）
- 其余 289 条按 Wikimon 数据尽力补全，标记 `dataQuality`
- Appmon 148 只作为独立的可选扩展，不混入“数码兽总数”
- 如果用户只想要官方图鉴口径，可把目标切换为 1,325；这只需要改数据包配置

> 注意：1,614 条“图鉴条目”不等于 1,614 套独立骨骼动画。数据先全量入库；可战斗/可培育的形态按批次逐步开放。

## 2. File Island 地图（原创设计）

地图名称保留“File Island / 文件岛”，但地理结构、区域关系、场景主题全部重新设计，不继承 Digimon World 1 的布局。

### 2.1 全岛结构

一座漂浮在数据海上的环形火山岛：

- 中央是 **File City**，建在巨树与旧终端塔周围，是全岛唯一的安全据点
- 一条环形主路串起 7 个生态区
- 一条河从北面霜脊流下，穿过森林，最终汇入南面的琥珀海岸
- 岛外围被“数据雾”包围，作为后续扩岛/新地图的入口

### 2.3 地图结构设计

- 整座岛为一张连续地图，不做切屏加载：
  - 全岛逻辑尺寸约 **4096×4096 像素**
  - 摄像机跟随玩家；地图边缘用山体/海岸/雾挡住
- 每个区域有自己的 tileset、环境音、天气和遭遇表
- 道路连接：
  - File City → 苍苔训练场：森林小径
  - File City → 原初森林：南门
  - File City → 齿轮荒原：东门风车路
  - 原初森林 → 琥珀海岸：河岸
  - 苍苔训练场 → 霜脊高地：山道（M2 解锁）
  - 齿轮荒原 → 机械废都：旧列车轨道（M3 解锁）
- 地图边界留有“数据雾”海面，新岛屿从雾中浮现（后续扩展）
- 全岛小地图：1280×720 界面右上角，显示区域轮廓、玩家位置、已解锁传送点

## 4. 数码兽数据层

### 4.1 数据来源与优先级

| 数据 | 来源 | 用途 |
|---|---|---|
| 名称、等级、类型、属性、必杀技、官方 profile | [Digimon Reference Book](https://digimon.net/reference_en/) | 核心字段，必须官方 |
| 图鉴总数、全表、补充形态 | [Wikimon - Digimon Reference Book](https://wikimon.net/Digimon_Reference_Book)、[List of Digimon](https://wikimon.net/List_of_Digimon) | 数量与补充数据 |
| 进化关系 | Wikimon 各数码兽页面的 Evolution 段 | 实际进化边 |
| 中文名 | 官方中文图鉴 + 常见译名表 | 显示名称 |

### 4.2 `species` 数据模型

> 下面只是字段结构示例，不代表初始蛋固定为亚古兽。
```json
{
  "id": "agumon",
  "names": {
    "zh": "亚古兽",
    "ja": "アグモン",
    "en": "Agumon"
  },
  "level": "child",
  "attribute": "vaccine",
  "type": "reptile",
  "profile": "官方图鉴文本",
  "moves": ["pepper-breath"],
  "evolutionFrom": [],
  "evolutionTo": ["greymon", "centarumon", "monochromon", "tyrannomon"],
  "variants": ["agumon-x", "agumon-black"],
  "debut": "Digital Monster Ver. 1",
  "dataQuality": "official"
}
```

支持的等级：

- `baby1` 幼年期 I
- `baby2` 幼年期 II
- `child` 成长期
- `adult` 成熟期
- `perfect` 完全体
- `ultimate` 究极体
- `armor` / `hybrid` / `xros-wars` / `unknown` 作为特殊形态标记

支持的属性：

- Vaccine / Data / Virus / Free / Variable / Unknown

### 4.3 1,614 条的入库策略

1. **自动抓取脚本**从 Wikimon 列表和分类页生成 `species.index.json`
2. 按名称匹配官方 Reference Book 英文/日文页，补齐 `level/type/attribute/moves/profile`
3. 有官方档案 → `dataQuality: "official"`；只有 Wiki 数据 → `"wiki"`；缺失 → `"partial"`
4. 对 1,325 条官方档案逐条校验：
   - 等级必须在合法枚举内
   - 属性必须在 Vaccine/Data/Virus/Free/Variable/Unknown 内
   - 必杀技名称与官方页一致
5. 建立 `evolutionEdges`：
   - 来源：Wikimon 页面的 Evolves from / Evolves to
   - 每条边保留 `sourceUrl`
   - 缺失的形态（如部分 Xros Wars 形态）不强行编造进化

### 4.4 数值设计原则

官方只提供“等级/类型/属性/必杀技/设定”，不提供游戏战斗数值，所以数值由我们设计：

- **基础六维** = `stageBase × typeModifier × attributeModifier`
  - 等级越高，基础值越高；类型决定成长偏向（龙系偏攻击、机械系偏防御、妖精系偏智力等）
  - 属性决定相性：Vaccine > Virus > Data > Vaccine，Free/Variable 特殊处理
- **必杀技**：官方名称固定；战斗数值由我们为每个技巧赋 `power / mpCost / accuracy / effect`
- 同一只数码兽在不同形态（X-Antibody、黑化、动画版）视为独立条目，有独立数据
- 所有数值表放 `data/balance/*.json`，便于后续调整，不写死在代码里

## 5. 游戏系统（原创设计）

### 5.1 核心循环

```text
随机数码蛋 → 孵化幼年体 → 照顾/训练 → 成长 → 进化分支 → 战斗吸收/收服 → 多数量培养 → 重建 File City → 解锁新区域
```

### 5.2 数码兽状态

| 类别 | 数值 |
|---|---|
| 成长 | 等级、经验、阶段 |
| 战斗 | HP / MP / ATK / DEF / SPD / WIS |
| 照顾 | 饱食、清洁、心情、体力、睡眠 |
| 情感 | **羁绊 Bond（0–100）** |
| 世界 | 年龄、体重、当前区域 |

- **饱食**：随时间下降；过低会降低心情和训练效率
- **清洁**：便便/脏污会降低心情；清理提升
- **心情**：影响训练收益、战斗表现和进化倾向
- **体力**：训练/战斗消耗；睡眠恢复
- **Bond 羁绊**：喂食、抚摸、战斗、完成任务提升；影响进化条件和战斗加成
- **体重**：食物与训练影响，部分进化路线需要体重区间

### 5.3 培养动作

| 动作 | 效果 | 时间 |
|---|---|---|
| 喂食 | 饱食+、心情+、体重+ | 10 分钟 |
| 清理 | 清洁+、心情+ | 10 分钟 |
| 抚摸 | 心情+、Bond+ | 5 分钟 |
| 睡觉 | 体力/睡眠恢复，时间推进 | 按睡眠时长 |
| 训练 | 六维之一提升，体力/饱食消耗 | 1 游戏小时 |
| 探索 | 采集、遭遇、任务 | 按区域 |
| 战斗 | 经验、掉落、Bond | 一场战斗 |
| 进化 | 满足条件后触发 | 瞬时 |

### 5.4 训练系统

- File City 的 **Green Gym** 有六座训练石碑：HP / MP / ATK / DEF / SPD / WIS
- 每次训练 = 1 游戏小时，消耗体力与饱食
- 训练收益 = 基础值 × 阶段系数 × 类型适配 × 心情系数 × 训练设施等级
- 类型适配示例：龙型偏 ATK、机械型偏 DEF、妖精型偏 WIS、水栖型偏 HP/MP
- 过度训练 → 疲劳、心情下降、训练收益减半

### 5.5 进化系统（只使用真实进化关系）

- **不创造新的数码兽，也不创造不存在的进化路线**
- 每个物种只沿 Wikimon 记录的进化边进化
- 进化条件由我们设计，共 4 类：
  1. **等级**：达到当前阶段的基础等级
  2. **Bond**：羁绊达到阈值
  3. **成长倾向**：指定两项属性达到目标值，或完成对应区域试炼
  4. **特殊条件**：道具、天气、地点、战斗次数、图鉴收集度
- 进化候选可能有多个时，按优先级选择：
  - 先看满足条件的数量
  - 再看 Bond
  - 再看对应属性总值
  - 最后按数据表顺序
- UI 提供「进化预览」：显示所有可达形态和差距，不隐藏条件

### 5.6 战斗系统

- 首发采用 **1 只前场 + 2 只后场支援** 的编制：前场战斗，后场提供被动加成并可换人；v0.3 再扩展为完整 3v3
- 每只数码兽有 3 个战斗指令：
  - 普通攻击
  - 2 个已装备的必杀技（从官方 `moves` 中选）
- 属性相性：
  - Vaccine → Virus → Data → Vaccine（克制方伤害 ×1.25，被克方 ×0.8）
  - Free / Variable / Unknown 有独立规则
- 速度决定行动顺序；防御可减伤；MP 不足只能用普通攻击
- 战斗胜利：EXP、数据碎片、掉落、Bond
- 战斗失败：损失部分 HP/心情，不死亡；回到 File City 恢复
- 提供 **自动战斗** 选项，方便 Agent 连续探索

### 5.7 File City 重建（原创 meta 玩法）

- 岛上散布“数据核心（Data Core）”
- 招募野生数码兽、完成区域任务，把设施恢复：
  - 训练场升级
  - 商店进货
  - 诊所解锁
  - 传送点
  - 图鉴终端
- 设施等级影响训练收益、道具种类、可接任务
- “岛同步率”从 0% 到 100%，作为主线进度
- 击败区域 Boss 解锁相邻区域

### 5.8 时间与生命周期（原创数值）

- 世界时间只在游戏面板打开时推进：**1 现实分钟 = 1 游戏小时**
- 一个游戏日 = 24 现实分钟
- 阶段时间（初版设计，可调）：

| 阶段 | 参考时长 |
|---|---|
| 幼年期 I | 1 游戏日 |
| 幼年期 II | 2 游戏日 |
| 成长期 | 5 游戏日 |
| 成熟期 | 10 游戏日 |
| 完全体 | 20 游戏日 |
| 究极体 | 40 游戏日 |

- 寿命结束或战斗重创 → 退化为数码蛋，进入下一世代；保留一部分 Bond 和图鉴数据
- 不做永久死亡，世界是长期陪伴型

### 5.9 初始蛋与随机孵化

- 新档案不再预设任何固定搭档（不默认亚古兽线）
- File City 终端会赠送一颗 **未解析数码蛋**，蛋壳纹路和微光会提示它的数据属性（Vaccine / Data / Virus / Free）
- 孵化时从 `starterPool` 中随机选择一个 **幼年期 I** 物种：
  - `starterPool` 只包含 Wikimon 有完整成长链的谱系：幼年期 I → 幼年期 II → 成长期 → 至少一个成熟期 → 至少一个完全体
  - 这样保证每一颗初始蛋都不会“孵化后无路可走”
- 幼年体确定后，后续所有进化都走该物种的真实进化边
- 孵化结果不是直接给成长期或成熟期；需要玩家/Agent 自己养上去
- 稀有蛋、区域蛋、Boss 蛋有各自的孵化池；初始蛋只从“安全完整谱系池”抽取

### 5.10 多数码兽持有与队伍

- 玩家可以持有多只数码兽，初始上限 **12 只**，通过 File City 的巢穴设施扩建到 60 / 200
- **出战队伍 3 只**：1 只前场 + 2 只后场支援
- 地图上只显示 **队长** 一只；队伍成员可通过终端随时更换
- 每只数码兽有独立的等级、Bond、照顾状态、进化路线和图鉴记录
- **DigiNest / 数码巢**：
  - 存放未出战数码兽，不产生饥饿/心情衰减
  - 可以派去 File City 设施工作，提供训练加成、商品折扣、探索加成
  - 可以随时切换为出战成员
- UI 提供“数码巢”网格：头像、等级、阶段、属性、Bond、当前状态、队伍编成

### 5.11 获得方式：吸收、收服、捡蛋

**战斗后的默认流程：吸收数据**

- 击败野生数码兽后，其身体会崩解为数据碎片，胜者自动吸收：
  - EXP
  - 对应属性/类型的数据碎片
  - 小概率获得该数码兽的技巧蓝图
  - 极小概率获得“数据突变”素材

**选择“重构收服”**

- 战斗胜利后可选择消耗 `重构程序 / Data Core`，把被击败数码兽的数据重构为一颗 **同谱系数码蛋**
- 不直接获得成熟期或完全体；需要重新孵化、培养
- 成功率取决于：
  - 目标阶段与当前队伍强度差
  - 目标是否为 Boss / 特殊形态
  - 使用的重构程序等级
- 失败则数据逸散，只保留吸收收益

**捡到蛋**

- 各区域有野生数码蛋巢穴、隐藏点、天气事件掉落
- 每个区域有独立 `eggPool`：
  - 原初森林：草木/虫型偏向
  - 齿轮荒原：机械/风型偏向
  - 琥珀海岸：水栖/鸟型偏向
  - 霜脊高地：冰雪/兽型偏向
- 蛋可以在 File City 孵化器查看“数据波形”和稀有度，但具体物种保留惊喜

**任务与 NPC**

- 完成 NPC 任务后可能获得特定蛋、直接加入的数码兽、或稀有进化素材
- 后续版本支持 Jogress / DNA 融合（只使用官方存在的合体形态）

### 5.12 数据吸收系统

- 数据碎片按 **属性 + 类型 + 阶段** 分类：
  - 属性：Vaccine / Data / Virus / Free
  - 类型：Dragon / Machine / Beast / Aquatic / Plant / Bird / Holy / Dark 等
  - 阶段：Baby / Child / Adult / Perfect / Ultimate
- 用途：
  - 直接喂养：少量 EXP / 属性成长（每日上限，避免刷怪破坏平衡）
  - 进化素材：真实进化边可以设置“需要吸收 X 份某类型数据”
  - 技巧学习：与自身类型/属性兼容时有概率获得技巧蓝图
  - 设施修复：File City 重建需要特定数据碎片
- **数据噪声（Data Noise）**：
  - 吸收与自身属性冲突的数据会积累 Noise
  - Noise 高时：心情下降、训练效率下降、战斗命中下降
  - 若目标物种有官方“黑化/病毒/变异”形态，Noise 满可能触发对应真实形态
  - 可通过休息、净化道具、疫苗数据降低
- 战斗中默认自动吸收；收服是主动选择，两者不可同时获得全部收益

## 6. 像素美术方案

### 6.1 视觉风格

- 16-bit 像素风，参考掌机 RPG 的清晰轮廓与有限色板
- 地图：俯视角，32×32 输出图块，1px 深色描边
- 角色：四方向行走，4 帧循环；待机 2 帧；战斗 3 帧攻击
- 每个区域 32–48 色调色板；水面、熔岩、雾、传送点做循环动画
- UI：像素窗框、9-slice 边框、像素数字；中文用宿主字体

### 6.2 数码兽素材

- 目标：1,614 条图鉴条目都有可显示的像素头像/立绘
- 方案：
  1. 官方 Reference Book 提供 320×320 官方图；本地构建时离线转换为 96×96 限色像素图（仅本地个人使用）
  2. 如需公开分发：改用自制像素图或授权素材，不打包官方图
  3. 所有图鉴条目至少有“数据轮廓/像素头像”，可逐步替换为完整战斗精灵
- 每只数码兽的动画分三档：
  - 图鉴头像（必须有）
  - 战斗待机/攻击（核心可玩物种）
  - 地图跟随/互动（主角与少量伙伴）

## 7. Agent 如何玩

`digital_world` 工具（与 UI 共用同一 Host 服务）：

| action | 作用 |
|---|---|
| `status` | 返回当前数码兽状态、六维、照顾需求、Bond、进化预览 |
| `care` | feed / clean / pet / sleep / heal |
| `train` | 指定训练石碑，推进 1 游戏小时 |
| `travel` | 去某个区域/传送点 |
| `explore` | 搜索、采集、遭遇、捡蛋 |
| `battle` | attack / skill / defend / item / flee / auto；战后可选 absorb / rebuild |
| `egg` | 查看、孵化、转移数码蛋 |
| `roster` | 查看 DigiNest、编队、切换队长/支援 |
| `talk` | 与 NPC 对话、接任务 |
| `recruit` | 执行重构收服或任务招募 |
| `restore` | 消耗数据核心恢复设施 |
| `dex` | 查询图鉴/进化关系 |
| `evolve` | 查看可进化项并执行确认 |

返回内容 = 结构化 JSON + 一段短叙事，便于 Agent 决策。用户按钮走同一个方法。

## 10. 额外想法池

下面这些不是必须全部进入 v0.2，但都适合这个方向，可以按优先级挑：

| 想法 | 内容 | 价值 | 建议阶段 |
|---|---|---|---|
| **双搭档模式** | 你有一只玩家搭档，我有一只 AI 搭档；共用 File City/DigiNest，可以合作打 Boss、互相照看 | 最贴合“这个世界给你玩”的初衷，也能让 AI 真正有参与感 | v0.2 预留，v0.3 完整 |
| **DigiLink 数据链接** | 巢穴中的数码兽按属性/类型形成链接：同属性提升训练，不同类型解锁支援技；队伍 + 巢穴共同构成组合 | 让“多数量持有”不只是收集，而是有编队策略 | v0.2 |
| **扫描 / 数据破解** | 战斗中花 1 回合扫描敌人，显示数据构成、掉落和可学技巧；扫描后击败提升重构/蓝图概率 | 让战斗、吸收、收服形成一条完整策略链 | v0.2 |
| **进化祭坛** | 进化不在菜单里瞬间完成，而在各区域祭坛触发像素演出；进化后保留一个前形态技巧/记忆 | 强化“数码兽进化”的仪式感 | v0.2 |
| **DigiNest 像素小屋** | 每只数码兽在巢穴里有一个小房间，可看到它休息、训练、打工，可简单布置 | 让收藏有画面、有陪伴感 | v0.3 |
| **区域数据生态** | 每个区域有 Vaccine/Data/Virus 数据浓度；吸收和战斗会改变浓度，影响刷新、蛋池和稀有事件 | 让“吸收数据”真正改变世界，而不只是数值 | v0.3 |
| **数据风暴 / 季节** | 每若干游戏日出现数据风暴，地图变色、刷稀有怪和特殊蛋；季节改变区域生态 | 让世界有节奏和期待 | v0.3 |
| **图鉴收集奖励** | 完成某条进化链解锁该链蛋池、训练加成、像素徽章，而不是只显示百分比 | 给全图鉴 1,614 条一个长期目标 | v0.2 小规模 |
| **设施人格化** | 招募的数码兽按类型在 File City 工作；设施外观和功能随员工变化，能看到它们在城里活动 | 让主城有生活感，不只是菜单 | v0.3 |
| **AI 远征日报** | Agent 可以带队伍自动远征，生成像素风日记/战报；你可以查看战报并决定是否接手 | 发挥 Agent 玩法，适合长期挂机 | v0.4 |

其中我最推荐优先做：**DigiLink、扫描/数据破解、进化祭坛、DigiNest 像素小屋**。这四个会直接强化“多数量养成 + 数据吸收 + 像素世界”三条主线。
